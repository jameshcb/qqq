# 帮助 / FAQ 内容路由：落笔前两问 + 构建生成物

仅在 SKILL §3 判定「本窗可能改了别人照着做的操作口径」时读取。真源目录 = 项目声明的 `help_dir`，生成命令 = `help_generators`（声明格式见 README「qqq 项目声明」）。

## 判据回顾

判据 = 本窗有没有改动「别人照旧做就会做错」的东西：新界面、换了填法、改了术语、加了闸。纯数据变化（下拉从 1 条变 67 条）不改操作口径，表态写「无」并给这句理由。

## 落笔前两问

1. **读者是谁、这个载体有没有权限门。** 喂 AI 答疑的语料通常整份进 prompt 且零角色过滤，写进去等于全员可读。成本、供应商、底价这类要另走带权限门的载体。（实撞：某项目 FAQ 语料的门 = 任何登录用户，而销售 / 业务员有意不给 `supplier.read`。）
2. **写的是常青口径还是会过期的快照。** 条数、金额、「目前有 N 个」属于快照，进 sessions 不进帮助；帮助只留「什么情况怎么做」。

## 构建期生成物

帮助内容有构建期生成物（打包进 bundle 的语料 / 文档常量）时，改完 md 要重跑生成器并把生成物一起提交，否则同步测试会红、或线上仍是旧内容。项目声明了 `help_generators` 就跑那条命令；没声明但发现有生成物，在回报里提醒用户补声明。

## 背景

- 2026-08-29 James 拍「同步生成知识库」：此前帮助内容全靠临时想起来写，界面改了而帮助停在旧写法无人发现。
- 2026-09-01 James 拍：知识库的 per-deploy 义务移到项目侧（部署流程自带），qqq 降为**窗级兜底核对**——所以 §4 那行「帮助/FAQ:」要的是显式表态并落盘可验，不是替项目做同步。
